# 개발 로드맵 (Phase 1 → Phase 2)

## 전체 그림

```
[Phase 1] 말씀자료 모듈 (MVP)        [Phase 2] 보도자료 모듈
        │                                    │
        ├── W1: 인프라 셋업                   ├── 백엔드 모듈 분기 (module=press)
        ├── W2: 화면 1·2-B 기본 UI            ├── 화면 2-A·2-A-1 추가
        ├── W3: 업로드·추출 (2-B-1·2-B-2)     ├── 보도자료 구조·가드레일
        ├── W4: AI 생성 (5-Layer + 가드레일)   ├── cabinet.xml + dept_mois.xml 활용
        ├── W5: 화면 3·4 (결과·편집·MD 출력)   └── 통합 플랫폼 출시
        ├── W6: 화면 5·6 (이력·페르소나)
        └── W7: 통합 테스트 + 배포
                  │
                  └── [v2] HWPX 출력 추가 (PoC 후)
```

## Phase 1 주차별 작업

### 1주차: 인프라 셋업

**목표**: Cloudflare 인프라 + Next.js 스캐폴딩 완료, 「Hello World」 배포까지.

**작업**:
- [ ] Cloudflare 계정 확인·결제 카드 등록
- [ ] D1 데이터베이스 생성·마이그레이션 작성
- [ ] R2 버킷 생성 (24h TTL 라이프사이클 설정)
- [ ] KV 네임스페이스 생성
- [ ] Next.js 15 프로젝트 생성 (App Router + TypeScript + Tailwind)
- [ ] shadcn/ui 초기 설치 (Button, Form, Input, Select, Dialog 등)
- [ ] Wrangler Workers API 스캐폴딩
- [ ] Anthropic API 키 환경변수 설정
- [ ] 도메인·서브도메인 결정 + DNS 연결
- [ ] 「Hello World」 페이지 배포 확인

**산출물**: 동작하는 빈 Next.js 앱 + Workers API.

### 2주차: 화면 1·2-B 기본 UI

**목표**: 화면 1 홈 + 화면 2-B 말씀자료 입력 폼 완성 (업로드 기능 제외).

**작업**:

  - [ ] 5단계 분량 라디오 + 사용자 지정 (IN-17)
  - [ ] 발화자 직급 드롭다운 + 페르소나 자동 표시 (IN-14)
  - [ ] 핵심 메시지 태그 입력 (IN-18)

### 3주차: 업로드·추출 (화면 2-B-1·2-B-2)

**목표**: 행사계획서·참고자료 업로드 → 텍스트 추출 → 폼 자동 채움.

**작업**:
- [ ] 파일 업로드 UI (react-dropzone)
  - [ ] UP-01 단일 파일 (행사계획서)
  - [ ] UP-02 다중 파일 (참고자료)
- [ ] 백엔드 `POST /api/upload` 엔드포인트
- [ ] 텍스트 추출기 (DOCX·PDF·TXT·이미지)
  - [ ] DOCX: mammoth.js
  - [ ] PDF: pdf-parse 또는 pdfjs-dist
  - [ ] TXT: 직접 처리
  - [ ] 이미지: OCR 엔진 결정 후 (이번 주는 텍스트 파일만 지원도 OK)
- [ ] 민감정보 마스킹 (정규표현식)
- [ ] AI 자동 정보 추출 (행사계획서)
  - [ ] `POST /api/extract-event-info` 엔드포인트
  - [ ] 화면 2-B 폼 자동 채움 연동
- [ ] AI 자동 자료 분류 (참고자료)
  - [ ] 5종 분류 자동 판정
  - [ ] 사용자 수정 가능 UI
- [ ] R2 업로드·KV 컨텍스트 보존
- [ ] 컨텍스트 토큰 수 자동 계산·표시

**산출물**: 파일 업로드 → 폼 자동 채움 + 컨텍스트 보존 동작.

### 4주차: AI 생성 (5-Layer + 가드레일)

**목표**: AI 초안 생성 + 가드레일 자동 검증 완성.

**작업**:
- [ ] 5-Layer 프롬프트 모듈 구현
  - [ ] L1: 시스템 정체성
  - [ ] L2: 도메인 지식 (8개 행사 유형 + 6단/4단 구조 + 정형구 사전)
  - [ ] L3: 작성 규칙
  - [ ] L4: 컨텍스트 주입 (RAG 본문)
  - [ ] L5: 사용자 입력
- [ ] `POST /api/compose` Streaming 엔드포인트
- [ ] Claude API 스트리밍 호출
- [ ] 가드레일 자동 검증 (G-1~G-10)
  - [ ] 행사 유형별 차등 적용
- [ ] 분량 검증 (목표 ±10%)
- [ ] 생성 중 로딩 UI (단계별 진행 표시)
- [ ] 에러 처리 + 재시도 로직

**산출물**: 입력값 → AI 초안 생성 → 가드레일 검증 결과 표시.

## 일정 가이드

빅보스님 본업 + 다른 사이드 프로젝트 병행을 고려한 현실적 일정:

| 시나리오 | MVP 출시 시점 |
|---|---|
| 집중 (주 20시간 투입) | 7주 후 |
| 평이 (주 10시간 투입) | 14주 후 (≈3.5개월) |
| 여유 (주 5시간 투입) | 28주 후 (≈7개월) |

→ 다른 프로젝트(고유가지원금 운영·진료후 개발 등) 일정과 균형 맞춰 조정.

## 리스크 관리

| 리스크 | 영향 | 대응 |
|---|---|---|
| Claude API 비용 폭증 | 중 | 캐싱 전략 + Sonnet 4 우선, Opus 4는 정밀 모드만 |
| OCR 엔진 미결정으로 이미지 처리 지연 | 중 | MVP 초기에는 텍스트 파일만 우선 지원 |
| 부처 자체 자료 활용 어려움 | 낮 | speech.xml 50건만으로도 MVP 가능 |
| HWPX 호환성 미충족 | 낮 (MVP는 MD만) | v2로 미룸 |
| 빅보스님 시간 부족 | 높 | 한 주씩 끊어서 진행, 막히면 다음 주로 미루기 |
